# Heirloom program spec (source of truth for contract, IDL and TS client)

Every agent builds against this file. If you must change it, change it here first and say so in your report.

- Program name: `heirloom` (Anchor 1.2.2, Rust). Program id: **`b3PBVwkLnyx7eyLPNtc5J3Ds3os3cenqCVRHaCJM7FY`**
  (keypair at `target/deploy/heirloom-keypair.json`, gitignored; keep that file to keep the id). The TS side reads
  `NEXT_PUBLIC_HEIRLOOM_PROGRAM_ID`. The IDL is `app/src/lib/chain/idl/heirloom.json` (generated by `anchor build`).
- Money: USD₮ SPL token, 6 decimals. All amounts are `u64` base units (1 USD₮ = 1_000_000).
- Times: `i64` unix seconds from `Clock`.
- Hashes: `[u8; 32]` SHA-256 of the off-chain file/JSON. No personal data on-chain, ever.
- Token transfers use `transfer_checked` (token program = classic SPL Token; Token-2022 not required).
- Bitmaps: verifier index i (0..3) sets bit `1 << i`. Count with `count_ones()`.

## Instructions

Signer roles: **owner** (estate.owner), **agent** (estate.agent), **verifier** (one of estate.verifiers), **beneficiary** (wallet with an active Beneficiary PDA), **buyer**, **anyone**.

| # | Instruction | Args | Signer | Rules (error if broken) |
|---|---|---|---|---|
| 1 | `create_estate` | agent Pubkey, verifiers [Pubkey;3], death_threshold u8, claim_threshold u8, hardship_threshold u8, waiting_period_secs i64 | owner | verifiers distinct and ≠ owner; 1 ≤ thresholds ≤ 3; waiting ≥ 0; inits vault ATA; status Active; last_heartbeat = now |
| 2 | `set_will` | will_hash [u8;32], will_uri String | owner | status Active; uri ≤ 200 |
| 3 | `add_beneficiary` | label String | owner | Active; label ≤ 32. Accounts: wallet (unchecked) |
| 4 | `add_payee` | kind PayeeKind, name String | owner | Active; name ≤ 64. Accounts: wallet (unchecked) |
| 5 | `add_rule` | category, allowed_payee_kind, max_per_claim u64, lifetime_cap u64, valid_until i64, starts_now bool, recurring_amount u64, interval_secs i64, first_due i64 | owner | Active; max_per_claim ≤ lifetime_cap; both > 0. Accounts: beneficiary PDA, optional `payee` (Payee PDA); rule seeds use estate.rule_count, then rule_count += 1. If recurring_amount > 0: interval_secs > 0 (InvalidAmount), recurring_amount ≤ max_per_claim (ExceedsPerClaimCap), payee required (PayeeRequired) with kind == allowed_payee_kind (WrongPayeeKind); stores next_due = first_due, fixed_payee = payee.wallet. Otherwise interval/next_due = 0, fixed_payee = default and `payee` may be omitted (pass the program id = Anchor None) |
| 6 | `deposit` | amount u64 | owner | Active; owner ATA → vault |
| 7 | `withdraw` | amount u64 | owner | Active only; vault → owner ATA |
| 8 | `heartbeat` | – | owner | Active or DeathPending; last_heartbeat = now |
| 9 | `register_asset` | floor_price, hardship_floor, asking_price u64, proceeds_to Pubkey, doc_hash | owner | Active; floor ≥ hardship_floor > 0; asking ≥ floor; nft mint decimals 0; moves 1 NFT owner ATA → nft escrow (init_if_needed) |
| 10 | `submit_death_claim` | cert_hash | beneficiary | status Active; sets death_cert_hash, death_submitted_by, death_verdict Pending, attestations 0 |
| 11 | `review_death` | approve bool, report_hash | agent | a death claim exists (cert_hash ≠ 0); sets death_verdict. Reject clears the claim |
| 12 | `attest_death` | – | verifier | death_verdict Approved; bit not set; when count ≥ death_threshold → status DeathPending, death_pending_since = now |
| 13 | `veto_death` | – | owner | status Active or DeathPending → Active; clears claim fields; last_heartbeat = now |
| 14 | `finalize_unlock` | – | anyone | status DeathPending and now ≥ since + waiting → Unlocked |
| 15 | `submit_claim` | amount u64, evidence_hash | beneficiary | Unlocked, or Active if rule.starts_now (BadStatus); rule.beneficiary == signer; payee.kind == rule.allowed_payee_kind; amount ≤ max_per_claim; spent_total + amount ≤ lifetime_cap; now ≤ valid_until; claim seeds use rule.claim_count, then += 1 |
| 16 | `review_claim` | approve bool, report_hash | agent | claim Open & verdict Pending; reject → status Rejected |
| 17 | `approve_claim` | – | verifier | claim Open, verdict Approved; bit not set |
| 18 | `execute_claim` | – | anyone (payer of payee ATA rent) | Unlocked, or Active if rule.starts_now (BadStatus); claim Open, verdict Approved; approved = Active ? owner_approved : (owner_approved || approvals ≥ claim_threshold) (InsufficientApprovals); re-check lifetime cap & valid_until; vault → payee ATA (init_if_needed) signed by Estate PDA; spent_total += amount; status Paid |
| 19 | `list_asset` | duration_secs i64 | agent or verifier | Unlocked; asset Held → Listed; listing_ends = now + duration |
| 20 | `place_offer` | amount u64 | buyer | asset Listed; now < listing_ends; amount > 0; inits Offer + offer escrow; buyer ATA → offer escrow |
| 21 | `withdraw_offer` | – | buyer | offer escrow → buyer; close escrow + Offer (rent → buyer) |
| 22 | `submit_hardship` | evidence_hash | beneficiary | Unlocked; asset not Sold |
| 23 | `review_hardship` | approve bool, report_hash | agent | Open & Pending; reject → Rejected |
| 24 | `approve_hardship` | – | verifier | Open, verdict Approved; bit not set; when count ≥ hardship_threshold → Approved and asset.hardship_beneficiary = Some(beneficiary) |
| 25 | `accept_offer` | – | agent | asset Listed. Let r = recipient: if `hardship_beneficiary` is Some(b) → require amount ≥ hardship_floor, r = b; else require amount ≥ floor_price, r = proceeds_to. Atomically: offer escrow → r's USD₮ ATA (init_if_needed, payer agent); NFT escrow → buyer NFT ATA (init_if_needed, payer agent); close offer escrow + Offer (rent → buyer); asset Sold |

| 26 | `owner_approve_claim` | – | owner | estate Active, rule.starts_now (BadStatus); claim Open; verdict Approved (AgentNotApproved); not already (AlreadyApproved) → owner_approved = true. Accounts: owner(s), estate, rule, claim(w) |
| 27 | `execute_scheduled` | – | anyone (keeper; pays payee ATA rent) | rule.recurring_amount > 0 (BadStatus); Unlocked, or Active if starts_now (BadStatus); now ≥ next_due (NotDue); now ≤ valid_until (RuleExpired); spent_total + recurring_amount ≤ lifetime_cap (ExceedsLifetimeCap); vault → ATA(fixed_payee) (init_if_needed) signed by Estate PDA; spent_total += amount; next_due += interval_secs; emit ScheduledPaid |

**Living plans** (added 2026-11-11): a `starts_now` rule already works while the owner is alive (estate Active): claims need the agent + the **owner** (`owner_approve_claim`), verifiers alone are not enough; after unlock the verifier quorum (or an earlier owner approval) counts. Scheduled payments (`recurring_amount > 0`) are paid by anyone calling `execute_scheduled` once due. No minimum interval or waiting period: 60 s works for devnet demos.

Losing offers are returned by the buyer calling `withdraw_offer` (works in any asset state).

### Clarifications made while implementing (contract author, 2026-11-11)
- `submit_death_claim`: `cert_hash` must be non-zero (NoDeathClaim) and only one open claim at a time: fails with
  BadStatus if `death_cert_hash ≠ 0` (stops a second submission resetting attestations). A rejected or vetoed claim clears it.
- `review_death`: also requires status Active and `death_verdict == Pending` (BadStatus), so the agent can't re-review after DeathPending.
- `attest_death`: also requires a claim (NoDeathClaim); allowed in Active **or** DeathPending; only the attestation that
  reaches `death_threshold` starts the timer (later attestations don't reset `death_pending_since`).
- `create_estate` vault, `place_offer` escrow: `init_if_needed` (anyone can pre-create an ATA, which would otherwise block the call).
- `execute_claim`: also checks estate status (see row 18). `approve_hardship`: also requires asset not Sold (BadStatus).
- `list_asset` wrong signer → NotAgent; `duration_secs > 0` (InvalidAmount). `add_rule`: Beneficiary PDA must be active (NotBeneficiary); bad caps → InvalidAmount.
- `register_asset`: nft mint needs decimals 0 **and** supply 1 (InvalidNft); bad prices → InvalidAmount.
- `withdraw_offer` / `accept_offer` move the whole escrow balance (≥ offer.amount) so the escrow close can't fail.
- Mint checks: `usdt_mint` account `address = estate.usdt_mint` and every owner/buyer USD₮ token account `mint == estate.usdt_mint`, both → WrongMint.

## Off-chain hashing convention
`hash = sha256(bytes)`; for JSON use canonical JSON (keys sorted, no whitespace). Shown in UI as hex.

## Account names the TS client resolves (added by the backend agent, 2026-11-11)
`app/src/lib/chain/instructions.ts` resolves accounts **by name from the IDL** (case/underscore-insensitive), so any order works,
but names must be one of these. Preferred name first; aliases in brackets also work.
- Signers: `owner`, `agent`, `verifier`, `buyer`; beneficiary-signed ixs (submit_*): `beneficiary` = signing wallet + `beneficiary_account` = Beneficiary PDA (as in the IDL); `finalize_unlock` / `execute_claim`: `payer` [`signer`]; `list_asset`: `authority` [`signer`].
- PDAs: `estate`, `beneficiary` (the Beneficiary PDA in add_rule), `payee` (Payee PDA), `rule`, `claim`, `asset`, `offer`, `hardship`.
- Plain wallets (unchecked): `wallet` (add_beneficiary/add_payee), `payee_wallet`, `recipient` (accept_offer USD₮ receiver).
- Mints: `usdt_mint` [`mint`], `nft_mint`.
- Token accounts: `vault`, `owner_usdt` [`owner_token`, `owner_ata`], `owner_nft`, `nft_escrow`, `offer_escrow` [`escrow`], `buyer_usdt` [`buyer_token`], `buyer_nft`, `payee_usdt` [`payee_token`], `recipient_usdt` [`recipient_token`].
- Programs: `system_program`, `token_program`, `associated_token_program`, `rent` (fixed addresses in the IDL are used as-is).
- Args are passed **positionally in the order listed in the table above**, so arg names may differ.
